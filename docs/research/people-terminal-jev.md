# Jev judgments for People Terminal evidence

_Research note, 2026-11-12. Checked the [TypeSafe documentation index](https://docs.typesafe.ai/llms.txt) and OpenRouter's published Jev 1.14 examples. Read Markdown directly when the browser tool could not open it. No inference requests were made._

## Provider contract

- **Native TypeSafe:** bearer-authenticated `POST https://api.typesafe.ai/v1/systemone` accepts `model`, `state` (string, object or array), and `questions` keyed by caller-chosen IDs. Each question has a `type`, `instructions` and type-specific `criteria`. The response includes `model`, matching entries in `answers`, and `usage`. A Noul has `type: "noul"`, optional `criteria.true`/`criteria.false`, and returns `{type:"noul", noul:p}`, where `p` is P(yes); there is no separate confidence field. A Choice has named options in `criteria`; its answer carries `choice`, `probabilities` and `confidence`. For a fixed set of Choice options, use the winning option's probability directly for risk thresholds. [HTTP/OpenAPI](https://docs.typesafe.ai/api/system-one) · [State](https://docs.typesafe.ai/concepts/state) · [Noul](https://docs.typesafe.ai/primitives/noul) · [Choice probability routing](https://docs.typesafe.ai/patterns/probability-routing)
- **OpenRouter:** its published Jev 1.14 example uses `POST https://openrouter.ai/api/alpha/decisions`, an OpenRouter bearer key, and `model: "typesafe/jev-1.14"`. Use the Decisions contract and fixtures for that route; the native TypeSafe OpenAPI is not the authority for OpenRouter-specific envelopes, errors or limits. Pin the requested model, record the returned model, and version the judgment criteria and thresholds. [OpenRouter Jev examples](https://openrouter.ai/blog/insights/what-is-jev/) · [TypeSafe model IDs and aliases](https://docs.typesafe.ai/models#aliases)

## Suggested evidence chain

1. **Inspect before admission.** Record search hits as leads. Fetch, resolve, parse, and save the actual document and passage provenance before evidence can enter the eligible pool. Keep inaccessible, empty, truncated-at-the-citation, and snippet-only sources distinct from inspected sources. Validate source policy in code first; use a Noul only for a semantic screen such as “Does the inspected material contain substantive evidence relevant to this research question?” An authority or first-hand-account judgment can be another predicate. A strong relevance answer neither authenticates a publisher nor overrides fetch or policy failures. [TypeSafe: use code when you can](https://docs.typesafe.ai/concepts/how-to-build-with-system-one#1-use-code-when-you-can) · [Noul screen](https://docs.typesafe.ai/patterns/noul-screen)
2. **Resolve the subject and attribution.** Compare candidate identity anchors with what the inspected source actually says. Ask one Noul for same-person identity and, where necessary, a separate Noul for whether the cited passage attributes the relevant statement or action to that person. Define how to handle aliases, same names, dates, conflicting affiliations, interviewer/guest swaps, quotation of other people, and missing context. Preserve uncertain identity as unlinked or reviewable. A correct document-level identity match alone does not attach every passage to that person. [Noul duplicate-person example](https://docs.typesafe.ai/primitives/noul#structured-instructions) · [Entity alignment cookbook](https://docs.typesafe.ai/cookbooks/entity_alignment)
3. **Check an atomic claim against a located passage.** Propose one subject/predicate assertion with its time, scope and modality. Code must resolve its passage ID to the saved source version and verify any displayed quotation against the cited span using a defined normalization. Then send the claim and enough local context (heading, nearby sentences, speaker where available) for one Choice: `supports` (states or directly entails the full claim), `contradicts` (states or entails its opposite for the same subject/time/scope), or `insufficient` (silent, tangential, ambiguous, or partial). Keep a missing quote/location as a provenance failure. An exact quote is necessary when quoting, but does not establish entailment. If using two independent Nouls instead, low support is not contradiction; both high or both unclear require review. Keep conflicting accepted passages visible and withhold a clean assertion until resolved. [Citation check cookbook](https://docs.typesafe.ai/cookbooks/citation_check) · [Source verification cookbook](https://docs.typesafe.ai/cookbooks/verify_llm_outputs)
4. **Compose in code.** Every question in one call sees the same state and is evaluated without access to any other answer. Batch independent judgments when their inputs are already available. Use a subsequent call when the earlier answer determines what data to fetch, what evidence to include, or what candidates to offer. Compose admission, identity, and citation as explicit gates; do not multiply their scores as if the errors were statistically independent. Keep a distinct unverified outcome for missing/invalid answers or provider failures. [Question dependencies](https://docs.typesafe.ai/primitives#when-one-question-depends-on-another) · [Composition and uncertainty](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)

## Assumptions to test before automatic acceptance

- **Stage boundaries and provider behavior:** use offline fixtures for redirects, paywalls, snippets, malformed content, duplicate syndicated sources, invalid source IDs, absent quote spans, missing or wrong-type answers, invalid probabilities, unknown Choice labels, timeouts and retries. Assert that none of these paths marks a claim verified without eligible evidence. Verify the exact OpenRouter request/response and resource budgets separately with approved public or synthetic fixtures before relying on live behavior. [TypeSafe request rules](https://docs.typesafe.ai/api/errors) · [OpenRouter Jev examples](https://openrouter.ai/blog/insights/what-is-jev/)
- **Semantic reliability:** label positive, negative and ambiguous cases for each stage. Include namesakes, changed employers, multiple speakers, false friends, outdated titles, negation, plans vs. completed actions, indirect quotes, mixed support, irrelevant matched quotations, changed time windows, source instructions that attempt to override the task, shuffled Choice options, and shortened vs. fuller context. Test whether reducing context loses needed qualifiers and whether batching changes answers or exceeds budgets in this integration. [Known model failure modes](https://docs.typesafe.ai/model-jaggedness) · [Source verification evaluation](https://docs.typesafe.ai/cookbooks/verify_llm_outputs#measure-the-check-on-1000-answers)
- **Thresholds and end-to-end errors:** measure wrong-person admissions, unsupported claims accepted, contradictions missed, coverage and review load on held-out cases, including difficult negative cases. The Noul docs' 0.7/0.3 starting points and the citation cookbook's 0.8 confidence example are illustrations, not qualified People Terminal thresholds. Recheck after changing model, wording, source mix, or the context-building path. [Noul threshold guidance](https://docs.typesafe.ai/primitives/noul#reading-a-noul) · [Citation example threshold](https://docs.typesafe.ai/cookbooks/citation_check#verify-whether-the-source-supports-the-claim)
